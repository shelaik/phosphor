01 Cos'è

Phosphor legge la cartella locale ~/.claude e ti mostra tutte le tue sessioni di Claude Code — dove giravano, cosa hanno fatto, a che punto sono — in un'app nativa a tutto schermo nel terminale (TUI retro a fosfori), in una dashboard nel browser, oppure come avventura grafica pixel-art.

Sola lettura. Phosphor non modifica e non invia mai i tuoi transcript. Ogni azione che scrive qualcosa sul disco lo spiega prima e chiede conferma.

02 Avvio

App nativa (consigliata)

Doppio click su phosphor.exe → si apre la TUI a tutto schermo, niente browser.

phosphor              # TUI (default)
phosphor --pixel      # grafica a "pixel"

Dashboard web

Server locale (solo 127.0.0.1), si apre nel browser.

phosphor --web                 # http://127.0.0.1:8787
phosphor --web --port 9000     # porta custom
phosphor --web --no-open       # non aprire il browser

Avventura grafica

Finestra vera (pixel-art SCUMM): doppio click su phosphor-adv.exe.

Un'altra cartella .claude

Per ispezionare i dati di un altro percorso/PC.

phosphor --dir C:\percorso\a\.claude
Ognuno usa la propria copia: il binario rileva da solo %USERPROFILE%\.claude dell'utente corrente. Per Riprendi serve che claude sia nel PATH.

06 Porting tra PC (export / import)

Sposta delle sessioni su un altro computer portando anche le sottocartelle (transcript principale + sub-agenti/workflow) in un unico file .phx.

# sul PC di origine
phosphor export-all                      # -> Desktop\phosphor-sessioni-AAAAMMGG-hhmmss.phx
phosphor export-all --project nome       # solo un progetto
phosphor export-all --out D:\backup.phx  # percorso a scelta

# copia il .phx sull'altro PC, poi:
phosphor import D:\backup.phx            # mostra cosa aggiungerà e chiede conferma

Dalla TUI: x crea il bundle delle sessioni in vista; i importa il .phx più recente trovato sul Desktop (o nella cartella .claude).

Import sicuro: rifiuta percorsi anomali, non sovrascrive file esistenti (li salta), e chiede sempre conferma. Può solo aggiungere i transcript mancanti.

07 Limiti del piano

phosphor limits (e la riga di stato in alto nella TUI) mostra il piano (es. Max 20x) e quando si resetta la finestra dei limiti, letti da ~/.claude.json.

Le percentuali ufficiali delle finestre 5h / settimanale non sono salvate in locale (Claude le riceve a runtime), quindi non vengono mostrate: Phosphor riporta solo ciò che è realmente disponibile sul disco, senza stime fuorvianti.

08 Audit di sicurezza

Phosphor è pensato per essere condiviso. Prima della distribuzione è stato fatto un controllo completo e applicate queste difese (tutte verificate con test, build pulito e selftest).

DNS-rebinding

Server solo loopback + verifica Host

La dashboard web ascolta solo su 127.0.0.1 e rifiuta (403) ogni richiesta con header Host non locale, bloccando gli attacchi di DNS-rebinding da pagine esterne.

CSRF

Azioni solo POST same-origin

Gli endpoint che agiscono (/api/resume, /api/refresh) accettano solo richieste POST con Origin dello stesso sito: nessun altro sito può innescarle, e non si attivano via semplice GET.

XSS

Escaping output + Content-Security-Policy

Tutto ciò che finisce nella pagina viene escapato (& < > " ') e una CSP restrittiva limita cosa il browser può eseguire o caricare.

CSV formula injection

Celle neutralizzate

Nei file CSV esportati, i valori che iniziano con = + - @ (o tab) vengono prefissati con un apostrofo, così Excel/Sheets li trattano come testo e non eseguono formule malevole.

Command injection

"Riprendi" blindato

L'id sessione è validato ([0-9a-fA-F-], ≤40), la cartella di lavoro è rifiutata se contiene virgolette / caratteri di controllo / % e deve esistere; viene passata come argomento separato al sistema, mai interpolata in una stringa di shell.

Path traversal

Import dei bundle controllato

All'import, i percorsi con .., assoluti, con lettera di drive o separatori anomali vengono rifiutati; i file vengono scritti solo dentro projects/ e mai sovrascritti.

Denial of service

Parser e server con limiti

Il parser JSON custom ha un tetto di ricorsione (anti stack-overflow); il server limita le connessioni concorrenti e legge gli header con un tetto di dimensione e timeout, fallendo in modo sicuro su input incompleti.

Perdita / corruzione dati

Scritture atomiche & mai-sovrascrivi

Config e cache si scrivono con tecnica tmp+rename (niente file a metà). Gli export usano create-new con nomi che includono data/ora: non sovrascrivono mai nulla.

Azioni distruttive silenziose

Conferma sempre, niente bypass

Ogni azione che scrive o lancia processi (export, riprendi, import, pulizia) spiega cosa farà e chiede conferma. L'unica eliminazione possibile è clean --delete-empty (solo file .jsonl vuoti, sempre dopo conferma digitata): nessuna scorciatoia per saltarla.

09 Dati & file scritti

Phosphor scrive solo questi file (dentro .claude e, per gli export, sul Desktop):

FileCosa
phosphor.jsonla tua configurazione (tema, prezzi, budget…) — scrittura atomica
.phosphor-cache.v2.jsonlcache di scansione, rigenerabile (riscritta a ogni scan)
Desktop\phosphor-export-*CSV/JSON dell'export vista — data nel nome, mai sovrascrive
Desktop\phosphor-sessioni-*.phxbundle portabile di export-all — data nel nome, mai sovrascrive
I transcript delle sessioni non vengono mai modificati né inviati in rete. Phosphor legge anche ~/.claude.json in sola lettura per piano e reset limiti; non tocca il file delle credenziali.
